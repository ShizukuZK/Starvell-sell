# GitHub, версии и хостинг

## 1. Подключить GitHub (один раз)

1. Поставьте Git: https://git-scm.com/download/win (все настройки по умолчанию).
2. Запустите **`setup_github.bat`**. Он откроет github.com/new: создайте
   **приватный** (Private) репозиторий без README и вставьте ссылку в окно.
3. Git попросит войти в GitHub: окно входа откроется в браузере.

Папка `storage/` с ключами в репозиторий **не попадает**: это закрыто в
`.gitignore`, а скрипт перед отправкой проверяет это ещё раз.

## 2. Версии

| Что сделать | Как |
|---|---|
| Выпустить новую версию | `release.bat 2.1.1` → допишите изменения в CHANGELOG.md → готово |
| Обновить бота на ПК | закрыть бота → `update.bat` → `start.bat` |
| Посмотреть версию | панель → «ℹ️ Версия» |

`release.bat` меняет `version.py`, делает коммит и тег `v2.1.1` и отправляет
их на GitHub. Дальше GitHub Actions прогоняет тесты и создаёт Release с
описанием из CHANGELOG. Бот раз в 6 часов проверяет релизы и присылает в
Telegram «🆕 Вышла версия…».

Тесты запускаются на GitHub при каждом пуше (вкладка **Actions**). Красный
крестик значит, что версия сломана и выкатывать её не стоит.

Для **приватного** репозитория бот проверяет обновления только с токеном:
github.com → Settings → Developer settings → Fine-grained tokens → доступ к
одному репозиторию, право **Contents: Read-only**. Токен вставьте в
панели: ⚙️ → ⏱ Опрос и обновления → «Токен GitHub». На хостинге его можно
задать переменной `GITHUB_TOKEN`.

## 3. Railway

### Сколько стоит (цены с docs.railway.com/pricing/plans, сентябрь 2026)

Бот занимает около **165 МБ памяти** и почти не нагружает процессор. Больше
всего памяти уходит на библиотеку Telegram (aiogram), так что заметно
уменьшить расход не получится.

| План | Что даёт | Хватит ли боту |
|---|---|---|
| Trial | $5 разово на 30 дней | да, первый месяц бесплатно |
| Free | $1 в месяц, 0,5 ГБ RAM | **нет**: работа 24/7 стоит ≈ $1,7–2/мес, кредита хватит примерно на полмесяца, потом сервис остановится |
| Hobby | $5/мес, в них входит $5 использования | да, с запасом |

Для Trial карта не нужна, но аккаунт GitHub должен пройти проверку. Без неё
Railway даёт «Limited Trial» с урезанной сетью, и бот не достучится до
Starvell. Для Hobby нужна карта, а российские карты Railway не принимает.

### Запуск

1. https://railway.com → **Login with GitHub**.
2. **New Project → Deploy from GitHub repo** → выберите репозиторий бота
   (Railway попросит доступ к нему: дайте доступ только к этому репозиторию).
   Railway сам найдёт `Dockerfile`.
3. Сервис → **Variables** → добавьте:

   | Переменная | Значение |
   |---|---|
   | `STARVELL_SESSION` | cookie `session` со starvell.com |
   | `KOSELL_API_KEY` | ключ KOSell |
   | `TG_TOKEN` | токен бота от @BotFather |
   | `TG_ADMINS` | ваш Telegram ID (команда `/id`) |
   | `DRY_RUN` | `true` на первый запуск, потом удалить |
   | `GITHUB_TOKEN` | необязательно, для уведомлений о версиях |

   `TG_ADMINS` обязателен: без него админом станет первый, кто напишет боту.
   Прокси для Telegram на Railway не нужен, серверы за границей.
4. Сервис → правый клик → **Attach Volume** → Mount path: **`/data`**.
   Без тома настройки и аренды пропадают при каждой перевыкладке.
5. **Settings**:
   - Region: Europe (ближе к Starvell/KOSell);
   - Restart Policy: **Always**;
   - Replicas: **1** (две копии = двойная выдача заказов);
   - Serverless / App Sleeping: **выключено**;
   - включите **Wait for CI**: тогда Railway выкатывает только версии,
     прошедшие тесты.
6. **Deploy**. В **Deployments → Logs** появится `версия 2.1.0 · данные: /data`,
   а в Telegram придёт «🟢 Бот запущен».

Каждый пуш в `main` (и каждый `release.bat`) Railway выкладывает сам.

### Переезд с ПК на Railway

1. На ПК в панели: ⚙️ → **💾 Перенос данных → 📤 Скачать копию**.
2. **Закройте бота на ПК.** Две копии с одними лотами могут выдать один заказ
   дважды. Если копии всё же встретятся, в логах появится «‼️ … работает
   ДРУГАЯ копия бота».
3. Перешлите файл боту, который работает на Railway, → «✅ Загрузить».
   Переедут цены, привязки, активные аренды, тексты и статистика. Ключи в
   файл не попадают.
4. Проверьте, что всё работает, и уберите переменную `DRY_RUN`.

## 4. Хостинг с панелью Pterodactyl (SatxCloud и похожие)

Бот лежит в папке `bot`, в разделе **Запуск**:

| Поле | Значение |
|---|---|
| APP PY FILE | `bot/main.py` |
| REQUIREMENTS FILE | `bot/requirements.txt` |
| GIT REPO ADDRESS | `https://github.com/ВАШ_НИК/РЕПОЗИТОРИЙ` |
| GIT USERNAME | ваш ник на GitHub |
| GIT ACCESS TOKEN | токен с правом **Contents: Read-only** (как в п. 2) |
| AUTO UPDATE | включено |

Что происходит дальше:

- при каждом запуске сервера бот скачивает свежий код из GitHub и
  перезапускается с ним (в консоли строка `[обновление] …`);
- раз в 30 минут проверяет релизы: вышла версия через `release.bat` — сам
  ставит её и перезапускается, в Telegram приходит «🆕 Вышла версия…»;
- панель → «ℹ️ Версия» → **«⬇️ Обновить сейчас»** — обновиться вручную.

Папка `storage/` (ключи, аренды, привязки) при обновлении не трогается.
Файлы на сервере руками больше не правьте: при обновлении они заменятся
версией с GitHub.

## 5. Другие варианты

- **Свой VPS за границей** (оплата в рублях, 1 ГБ RAM от ~150–300 ₽/мес).
  Поставьте Docker, скопируйте проект, заполните `.env` по образцу
  `.env.example` и выполните `docker compose up -d --build`.
  Обновление: `git pull && docker compose up -d --build`.
- **GitHub Student Pack**:
  - Heroku: $13/мес на 24 месяца, этого хватает на worker 24/7 (`Procfile`
    уже есть), но нужна карта;
  - DigitalOcean: кредиты для студентов закончились в августе 2026;
  - Azure for Students: $100 без карты, но нужна учебная почта и поддержка
    страны. Для России, скорее всего, недоступно.
- **ПК**: бесплатно, но бот работает, только пока включён компьютер.
